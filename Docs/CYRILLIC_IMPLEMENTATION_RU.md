# Добавление кириллицы в CLIBSTool и Berwick Saga

Инструкция относится к исходникам CLIBSTool в этой папке и к переводу на базе английской версии игры. Она описывает необходимые изменения для добавления кириллицы поверх текущей реализации словаря. Номера строк указаны для текущих исходников, поэтому после правок ориентируйтесь также на названия методов.

Для русского перевода нужно согласовать четыре вещи: символ в тексте, его игровой код, ячейку с изображением буквы и ширину этой ячейки. CP932 уже умеет кодировать все 66 русских букв, включая Ё и ё. Словарные токены используют отдельный игровой диапазон `8540–85FC`. Для отображения букв необходимо подготовить PNG, игровые таблицы соответствий и ширины глифов.

## 1. Как сейчас проходит текст

| Вид текста | Код, который его записывает | Что хранится в игровом файле |
| --- | --- | --- |
| Обычные сценарии, обрабатываемые `ScriptReader` | `TuBS/ImportScript.cs`, методы `FindChar` и `ScriptReader` | 16-битный индекс символа в массиве `CodePage`, записанный в little-endian |
| DAT-сценарии | `TuBS/DatScript.cs`, вызовы `CP932Helper.ToCP932` около строк 256 и 272 | Байты игрового варианта CP932 |
| Простые строки `BinaryTexts`, включая строки с указателями | `BinaryTextManager.cs`, вызовы `ToCP932` около строк 352 и 422 | Байты игрового варианта CP932 |
| Строки `Complex` и `ComplexWithWordList` | `BinaryTextManager.cs`, строки 354–360; `CP932Helper.ToComplexEn` | Двухбайтовые коды букв, однобайтовые пробелы и управляющие элементы; в режиме словаря — также коды целых слов |

`TuBS/CodePage.cs` — это не реализация Windows CP932. Его массивы задают порядок глифов в игровых атласах. Важен именно индекс: `codePage[100]` описывает букву в ячейке 100.

Для CP932-текста игра должна дополнительно найти глиф по коду. Здесь используются два разных вида ресурсов:

- `sjistab.dat`: `SJIStab.EncodeTo` записывает последовательность двухбайтовых кодов с переставленными байтами, в порядке символов целевого шрифта.
- `sjis.tbl` в `comlfont.ar`, `comrfont.ar`, `commfont.ar`: содержит соответствия кодов и индексов глифов; `WordListProgram` записывает в неё индексы изображений слов.

Эти форматы нельзя обновлять одним и тем же методом без разбора их структуры.

## 2. Что именно даёт кириллица в CP932

Русский алфавит уже представлен следующими кодами:

| Буква | Байты CP932 |
| --- | --- |
| А | `84 40` |
| Ё | `84 46` |
| Я | `84 60` |
| а | `84 70` |
| д | `84 74` |
| е | `84 75` |
| ё | `84 76` |
| о | `84 80` |
| я | `84 91` |

Прописные занимают `8440–8460`, строчные — `8470–8491` с пропуском `847F`. Соответствия приведены в [таблице Microsoft CP932 на сайте Unicode](https://www.unicode.org/Public/MAPPINGS/VENDORS/MICSFT/WINDOWS/CP932.TXT). Не вычисляйте коды всех букв простым прибавлением номера: в диапазонах есть особенности, включая положение Ё и пропуск `7F`.

Это позволяет оставить `Encoding.GetEncoding(932)`: для самих русских букв не требуется CP1251, UTF-8 в игровых бинарниках или замена русских букв иероглифами. В текущих `ToCP932` и `CharToCP932` русская буква уже доходит до `encoding.GetBytes(...)` и получает свои два байта. Локальная проверка системным кодировщиком подтвердила преобразование всех 66 букв в 132 байта и обратно без потерь.

Поддержка в кодировке не создаёт изображения букв, не добавляет их в игровые таблицы и не меняет вместимость текстовых блоков. Для индексных сценариев CP932 вообще не выбирает номер глифа: это делает `CodePage`.

И ещё одно практическое ограничение: поддержка русского алфавита не означает поддержку любой кириллицы и любых типографских символов. Проверять нужно весь фактический набор перевода. Редактируемые `.txt` можно сохранять в UTF-8; кодировка текстового файла переводчика и кодировка игрового ресурса — разные уровни.

### Словарные коды

`CP932Helper.ToComplexEn` записывает словарные токены напрямую в игровом диапазоне `85 40–85 FC`, включая `85 7F`. Нумерация в `WordListProgram.GetTokenNumber` начинается с единицы: первый токен получает `85 40`, последний допустимый, №189, — `85 FC`. При чтении каждого словаря программа проверяет количество записей после удаления дубликатов и останавливается, если их больше 189.

Эти токены являются игровым расширением. Стандартный кодировщик CP932 используется для букв; словарные коды не нужно пропускать через него. Совместимость кодов букв с CP932 не означает полного совпадения игровой кодировки с Windows CP932.

## 3. Способ внедрения

Использовать штатные коды русских букв CP932 и разместить их глифы в игровых шрифтах. Словарь использует собственный диапазон `8540–85FC`; для добавления кириллицы его кодирование менять не требуется. Основная работа — согласовать исходные атласы, целевые индексы, ширины и игровые таблицы соответствий.

## 5. Единый русский алфавит

Создать `RussianCharset.cs` в пространстве имён `CLIBSTool`:

```csharp
namespace CLIBSTool;

public static class RussianCharset
{
    public const string Letters =
        "АБВГДЕЁЖЗИЙКЛМНОПРСТУФХЦЧШЩЪЫЬЭЮЯ" +
        "абвгдеёжзийклмнопрстуфхцчшщъыьэюя";
}
```

Для обращения из глобального `CodePage` добавить `using CLIBSTool;` либо писать `CLIBSTool.RussianCharset.Letters`.

Не заменять русские А, В, Е, К, М, Н, О, Р, С, Т, Х латинскими буквами из-за внешнего сходства. Изображения могут совпадать, но символы и их коды различаются. В PNG можно скопировать рисунок, а в таблице сохранить русскую букву.

## 6. Исходные PNG и настройки SourceFont

### Малые исходные атласы

В `Program.ApplySourceFont` дополнить существующий список `chars` русским алфавитом. Для каждого исходника сохранить его собственный старый порядок:

```csharp
// existingChars — точная прежняя строка chars этого исходного PNG.
chars: (existingChars + RussianCharset.Letters).ToCharArray()
```

Здесь `existingChars` — обозначение строки в примере, а не существующая переменная проекта. В реальной правке можно вынести строки в именованные константы.

В PNG дорисовать 66 ячеек в точно таком же порядке, слева направо и сверху вниз. Простое изменение `chars` без изображения добавленных ячеек не создаёт шрифт.

| `13/townarea.ar/font.ttx.png` | `Program.cs:77` | 18 × 16 | 32 |
| `14/helpmsg.ar/font.ttx.png` | `SourceFontFactory.CreateHelpMsg` | 18 × 20 | 32 |
| `14/helpmsgb.ar/font.ttx.png` | `Program.cs:101` | 18 × 19 | 32 |

| `14/comrfont.ar/font0.ttx.png` | `SourceFontFactory.CreateComr` | 22 × 22 | 46 |

В `CreateHelpMsg` также расширить `chars`. Этот исходник используется и для `commfont`, и для изображений слов из `15WordList.txt`.

Минимальная высота исходного PNG равна `ceil(chars.Length / columns) * height`. Дополнительная ширина изображения не означает дополнительные колонки: код использует параметр `collumns`.

### Исходники coml и comr

Сейчас `SourceFontFactory.comChars` берётся из `CodePage.GetCodePage(-1, mode: "import")`, то есть описание исходного PNG связано с общей игровой раскладкой. Просто дописать русский алфавит в конец этой таблицы нельзя: `SourceFont` не поддерживает чтение второй страницы исходника и в `GetActualKerning` выбрасывает `to do second page in SourceFont`.

Удобный вариант — подготовить отдельные компактные исходные PNG для `coml` и `comr`, задать им отдельный `chars` и поправить `path` в фабрике. Их алфавит должен включать русские буквы, пробел `\u3000`, сохраняемые немецкие символы и все латинские буквы, цифры и знаки, реально встречающиеся в словарях. Порядок ячеек такого исходника может отличаться от целевого: `TypeCharacter` ищет исходную и целевую позицию раздельно.

### Фильтры копирования

В `Program.cs` дополнить все три `charsToType`:

```csharp
// commfont.ar, около строки 93
charsToType: ("ÄäÖöÜüß„”&=" + RussianCharset.Letters).ToCharArray(),

// comrfont.ar, около строки 163
charsToType: ("ÄäÖöÜüß„”&" + RussianCharset.Letters).ToCharArray(),

// comlfont.ar, около строки 170
charsToType: ("ÄäÖöÜüß„”" + RussianCharset.Letters).ToCharArray()
```

Без этих правок русские глифы из исходника не попадут в соответствующие игровые шрифты. Перед запуском у каждой перечисленной буквы уже должна существовать допустимая целевая позиция.

## 7. CodePage и размещение глифов в игре

### Малые целевые таблицы

Исправлять ветку `import` в `TuBS/CodePage.cs`, начиная примерно со строки 238. В небольших таблицах можно дописать `RussianCharset.Letters` к старой строке, **если хватает ячеек целевого PNG, записей ширин и ёмкости ресурса**. Это сохраняет старые индексы.

Проверить все группы: `0`, `1/2457`, `2/2460`, `4`, `6`, `11`; ресурсы `13/areanml.ar`, `13/townarea.ar`, `13/mission.ar`, `13/evitem.ar`; ресурсы `14/helpmsg.ar`, `14/helpmsgb.ar`, `14/smenui.ar`, `14/sysfont.ar`, `14/namene.ar`; номера `549`, `552`, `2256`, `2257`, `2261`, `2263–2279`, `2284`, `2449`, `2455–2460`, `2462`.

Не унифицировать их старые строки вслепую. В некоторых таблицах пробел стоит сразу после `ABCD`, а в `2264` нет блока цифр. Сдвиг старых индексов изменит уже существующие тексты.

Если места не хватает, есть два решения: переиспользовать проверенные ненужные ячейки с переупаковкой затронутых текстов либо расширить ресурс с учётом TTX, таблицы ширин и счётчиков движка. Увеличение одного PNG не является готовым расширением игрового шрифта.

### Общая таблица для диалогов и com-шрифтов

Большой общий `return` начинается около строки 312. Здесь нельзя просто дописать алфавит. Некоторые кириллические символы уже встречаются в таблице; например, `Д` и `д`. Поиск через `Array.IndexOf` и `FindChar` выберет первое вхождение, даже если новый рисунок помещён в другую ячейку.

Нужно составить явную карту «русская буква → целевой индекс»:

1. Найти 66 подходящих позиций или сохранить часть уже пригодных позиций и добавить недостающие.
2. Проверить, что заменяемые позиции не нужны оставшимся английским и японским строкам. Сохранить снимок прежней раскладки для их декодирования.
3. Согласовать `CodePage[index]`, рисунок и ширину. Не оставлять ситуацию, когда кодировщик выбирает одно вхождение буквы, а обновляется другое.
4. Для CP932-текста записать соответствие «штатный код русской буквы → этот индекс» в `sjis.tbl` каждого используемого com-шрифта.
5. Для индексных сценариев переупаковать затронутые тексты после изменения раскладки.

По параметрам `WordListProgram` первые страницы com-шрифтов имеют следующие логические размеры: `coml` — `51 × 39 = 1989` ячеек, `comr` — `46 × 46 = 2116`, `comm` — `46 × 40 = 1840`. Для общей карты, рассчитанной на существующую запись в `font0`, ориентир — индексы меньше `1840`, с дополнительной проверкой фактических PNG и остальных шрифтов, использующих эту карту. Это граница страницы, **не готовый список свободных ячеек**.

`SourceFont.TypeToTarget` пишет только в указанный PNG. Закомментированные строки `//second: ...` в `Program.cs` не включают поддержку второй страницы.

### Разделение исходной и целевой раскладки

В начале `CodePage.GetCodePage` стоит принудительное `mode = "import"`, если `Config.IsoType == "English"`. После замены существующих позиций это мешает отличить исходный английский ISO от русского результата.

Если все старые позиции сохранены, первоначальная распаковка английских строк остаётся совместимой в этой части. Если позиции заменяются, сохранить отдельные исходную английскую и целевую русскую раскладки и выбирать их явно. Сначала распаковывать исходный текст по старой таблице, затем импортировать перевод по новой. Японскую ветку `export` не заменять русским алфавитом.

В `SourceFont.cs:114` целесообразно явно запросить целевую таблицу:

```csharp
var codePage = CodePage.GetCodePage(data3Num, arName, mode: "import");
```

Это устраняет зависимость применения шрифтов от побочного переключения режима через `IsoType`. При введении отдельных профилей здесь должен выбираться именно русский целевой профиль.

## 8. CP932Helper и проверки ошибок

### Оставить CP932, включить строгую проверку

В статическом конструкторе `OtherLegacy/CP932Helper.cs` заменить создание кодировщика:

```csharp
encoding = Encoding.GetEncoding(
    932,
    EncoderFallback.ExceptionFallback,
    DecoderFallback.ExceptionFallback);
```

Регистрацию `CodePagesEncodingProvider.Instance` сохранить. Строгий декодировщик предназначен для обычных CP932-данных; игровые словарные коды нужно разбирать отдельно. Если старые дампы содержат нестандартные байты, для них понадобится отдельный явно выбранный режим чтения.

В двух местах, где сейчас без проверки читается `bt[1]` — конец `ToCP932` около строки 151 и конец `CharToCP932` около строки 348 — использовать общий метод:

```csharp
private static (byte, byte) EncodeDoubleByte(char ch)
{
    byte[] bytes = encoding.GetBytes(ch.ToString());
    if (bytes.Length != 2)
        throw new InvalidDataException(
            $"Ожидался двухбайтовый игровой символ: '{ch}' U+{(int)ch:X4}");
    return (bytes[0], bytes[1]);
}
```

В `ToCP932` результат добавить двумя `AddByte`, в `CharToCP932` вернуть этот кортеж. Это проверка именно ветки двухбайтовых глифов. Обработку перевода строки, пробелов, `%`-параметров, кнопок и специальных символов выше по методу сохранить.

Не заменять весь `ToCP932` на `encoding.GetBytes(input)`: существующий код записывает латиницу полноширинными кодами, имеет свой код пробела и игровые замены. Для русского алфавита новая таблица замен не нужна при выборе штатных кодов.

В `ToCP932(input, byteSize)` переполнение сейчас печатает сообщение и обрезает данные, но не выставляет `HasErrors`, в отличие от `ToComplexEn`. Сделать переполнение фатальной ошибкой, предпочтительно исключением до сохранения результата. Аналогично проверять, что строка вместе с завершением помещается в блок. Перевод на CP932 не увеличивает выделенные блоки.

### Защитить импорт индексных сценариев

В `TuBS/ImportScript.cs` двухаргументный `FindChar` использует `10000` как признак отсутствия. Сохранить этот внутренний поиск, но в трёхаргументном методе после проверки обеих таблиц выбрасывать ошибку:

```csharp
private static ushort FindChar(char ch, char[] codePage, char[] secondCodePage)
{
    ushort result = FindChar(ch, codePage);
    if (result == 10000)
        result = FindChar(ch, secondCodePage);
    if (result == 10000)
        throw new InvalidDataException(
            $"Нет глифа для '{ch}' U+{(int)ch:X4}");
    return result;
}
```

В сообщении вызывающего кода полезно добавлять имя файла и номер строки. Это позволит обнаружить неполную русскую таблицу до запуска игры.

```text
DATA3/2449/sjistab.dat
```

Их `charString` должен соответствовать **целевой** раскладке, включая порядок русских букв и положение пробела. Надёжнее получать строку из той же таблицы, которую использует запись шрифта, вместо девяти отдельных копий алфавита:

```csharp
SJIStab.EncodeTo(
    "DATA3/13/evitem.ar/sjistab.dat",
    new string(CodePage.GetCodePage(13, "evitem.ar", "import")));
```

Пример применим после согласования `CodePage` и шрифта. Кодирование пробела `\u3000` уже поддержано в `CP932Helper`.

В `OtherLegacy/SJIStab.cs` сейчас вызывается строковый `ToCP932(charString)`. Он добавляет нулевые байты завершения и выравнивания. Поэтому это не просто `число глифов × 2` байт. При расширении списка такая запись может затронуть записи после него.

Выделить кодирование одного игрового глифа в отдельный доступный метод, сохранив специальные правила и немецкие замены. В `EncodeTo` записывать пары в существующем порядке `младший байт, старший байт`; например, код А `84 40` должен дать запись `40 84`. Проверять вместимость таблицы до записи. Завершение, число записей и очистку хвоста задавать отдельно согласно формату конкретного ресурса: не переносить строковое выравнивание вслепую и не удалять нужный игре терминатор без проверки.

## 10. Русские буквы и словарь в sjis.tbl

В `sjis.tbl` шрифтов `comlfont.ar`, `comrfont.ar`, `commfont.ar` должны быть записаны соответствия штатных русских кодов `8440–8460` и `8470–8491` (с пропуском `847F`) целевым индексам русских глифов. Эти записи нужно согласовать с `CodePage`, рисунками букв и их ширинами.

Словарь занимает отдельный диапазон `8540–85FC`. `WordListProgram.InitWordList` начинает запись со смещения `1512` и последовательно записывает по два байта на токен: индекс изображения слова или `0` для неподходящего `tag`. Нумерация одинакова для `coml` и `comr`; `comm` использует собственный список с той же схемой кодов. Изображения слов размещаются начиная с индекса `2478`.

В разобранных обращениях движка к таблице для старшего байта меньше `E0` байтовое смещение вычисляется как `2 * ((lead - 0x81) * 189 + trail - 0x40)`. Поэтому диапазон словаря занимает байты `1512–1889`: для всех 189 записей требуется размер файла не меньше `1890` байт. Все три проверенные рабочие таблицы имеют размер `17766` байт; места достаточно.

При подготовке русского шрифта записывать соответствия русских букв в область `84xx`, сохраняя словарную область `85xx`. После изменения раскладок переупаковать зависимые тексты и проверить в одном шрифте отдельные русские буквы и словарные слова.

## 11. Проверки в SourceFont

До изменения файлов добавить проверку всех запрошенных букв:

- В исходном `chars` есть буква, и её исходная ячейка помещается в PNG.
- В целевой таблице выбран правильный индекс этой буквы.
- Индекс меньше длины `fontsize.dat` или `kerning.dat`.
- Целевая ячейка помещается в PNG с учётом `targetCols`, `cellDelta` и `drawingOffsetY`.
- Рассчитанная ширина допустима для формата и не превращается в большое положительное число после приведения отрицательного значения к `byte`.

Проверки нужны не только в `TypeCharacter`, но и в `GetLetterBitmap`, `GetLetterKerning`, `CountPixelSizeForWord`: эти методы вызываются при рисовании русских словарных токенов.

У Ш, Щ, Ж, Ы, Ю, Д, Ц и букв с диакритикой проверить ширину, нижние элементы и верхние точки. В `FillKerning` ширина определяется по прозрачным колонкам; внутренние промежутки рисунка могут влиять на результат. При необходимости задать `specialKerings` для отдельных букв или уточнить измерение по крайнему непрозрачному пикселю. Проверять нужно и шрифты с уменьшением ячейки через `cellDelta`.

В `WordListProgram.InitWordList` также проверить фактический конец размещаемого слова относительно страницы и `fontCharSize`. Текущая проверка сравнивает номер колонки с общей ёмкостью и сама по себе не гарантирует, что размещение не вышло за последнюю строку атласа.

## 12. Порядок внедрения и проверки результата

1. Сохранить исходные ресурсы и распакованные английские тексты до изменения раскладок. Для этой инструкции рабочая база — `Iso Type=English`; не вводить `Iso Type=Russian` без реализации соответствующей логики.
2. Проверить штатные русские коды на коротком CP932-тексте и одном целевом шрифте.
3. Задать русские позиции в целевых таблицах и подготовить все исходные PNG. Добавить проверки отсутствующих глифов и вместимости.
4. Согласовать `sjistab.dat`, `sjis.tbl` и словарные коды. Перепаковать строки, зависящие от изменённых индексов и токенов.
5. Запустить обновлённый инструмент из рабочей папки ресурсов:

   ```powershell
   .\CLIBSTool.exe ApplySourceFont
   .\CLIBSTool.exe PackAll
   ```

   `PackAll` нужен при первом переходе раскладок: изменения кода сами по себе не меняют размер и время текстовых файлов, поэтому обычный `Pack` может не переимпортировать все сценарии. Для следующих обычных правок использовать `Pack`.

6. Проверить в игре диалоги, имена, меню, справку, карту и экраны с `coml`, `comr`, `comm`. Отдельно проверить строки DAT и `BinaryTexts`.

Тестовый набор букв:

```text
АБВГДЕЁЖЗИЙКЛМНОПРСТУФХЦЧШЩЪЫЬЭЮЯ
абвгдеёжзийклмнопрстуфхцчшщъыьэюя
Ёж, щука, подъезд, съешь ещё этих мягких булок.
е ё ж о я
```

Для CP932-пути проверить байты букв и обратное декодирование. Для индексного пути проверить, что записан индекс из нужного `CodePage`, а не `0x8440` и не Unicode-код буквы. Для словаря проверить в одном шрифте отдельные русские буквы, слово первого токена `85 40` и их соседство в строке.

Сохранить в тестах латиницу, цифры, пробелы, переводы строк, `%`-параметры и управляющие маркеры сценариев. Проверить, что неизвестный символ, нехватка места в строке и отсутствие ячейки останавливают упаковку с понятной ошибкой. Проверить сохранность русских букв и словарных слов при повторном `Pack` после `ApplySourceFont`.

Готовность означает, что все эти пути показывают правильные буквы и слова в игре. Успешное преобразование строки в CP932 подтверждает только кодирование; оно не подтверждает работу игровых шрифтов и декодировщика.
